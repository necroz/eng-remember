# Батч B: тренировка вне FSRS

Дизайн-документ. Идея 5 дорожной карты: режим квиза по случайным карточкам,
который ничего не пишет в расписание, серию и статистику.

## Зачем

Между повторениями есть пустые дни: очередь пуста, а слова хочется погонять.
Сейчас единственный вход — `/review`, и он либо пуст, либо тратит интервалы.
Нужен лёгкий режим «просто потренироваться».

## Решения человека (из Q&A)

- Формат: квиз из 4 вариантов перевода.
- Без отдельной статистики; карточки выбираются случайно.

## Мои решения (можно оспорить)

1. В тренировку попадают только карточки, уже показанные хотя бы раз
   (`reps > 0`) и не на паузе: новые слова не спойлерятся до первого повторения.
2. Дистракторы берутся из переводов других своих карточек, приоритет — та же
   часть речи (`part_of_speech`), затем любые. Минимум для старта — 4 карточки
   с четырьмя разными переводами; иначе экран «пока мало слов».
3. Сессия — до 10 вопросов (`BOT__PRACTICE_SIZE`, дефолт 10), конец — по
   вопросам сессии. Ничего не сохраняется: счёт «верно N из M» живёт только в
   сообщении.
4. Серия и день не затрагиваются: день засчитывает настоящее повторение.
5. В FSRS не пишется ничего: ни `reviews`, ни `reps`, ни `due_at`.
6. Случайность — Python-`random.Random`, инжектируемый в сервис для
   детерминированных тестов.
7. Вход: команда `/practice`, кнопка «🏋️ Тренировка» в главном меню и инлайн
   «🏋️ Потренироваться» на экране «повторять нечего» (когда карточек хватает).
8. В `PracticeCB` едет токен сессии: без него вопрос №2 старой сессии и
   вопрос №2 новой не различить (одинаковые индексы), и устаревший тап
   принялся бы за текущий. Токен генерируется на старте сессии
   (`secrets.randbelow(10**9)`), живёт в FSM.
9. Как и в повторении, ответ резервируется ключом «в полёте»: aiogram
   обрабатывает апдейты конкурентно, и двойной тап без резервации удвоил бы
   счёт и отправил следующий вопрос дважды.

## Не-цели

- Никаких квизов с аудио/картинками, никаких «режимов» внутри тренировки.
- Никакого влияния на FSRS, серию, похвалы.
- Никакой персистентной статистики тренировок.

## Дизайн

### Сервис

`services/practice.py`:

```python
MIN_PRACTICE_CARDS = 4

@dataclass(frozen=True, slots=True)
class QuizQuestion:
    card_id: int
    term: str
    options: tuple[str, ...]   # переводы, включая верный
    correct_index: int

class PracticeService:
    def __init__(self, *, cards: CardRepository, settings: Settings,
                 rng: random.Random | None = None) -> None
    async def build_session(self, user: User) -> list[QuizQuestion]
```

- `build_session` берёт пул `cards.list_seen(user.id)` (новый метод
  репозитория: `reps > 0`, `is_suspended = False`, предел 500), проверяет
  «хватает ли разных переводов» (после нормализации), сэмплит до
  `settings.bot.practice_size` карточек и строит вопросы: 3 дистрактора на
  вопрос, приоритет same-POS, исключение переводов, совпадающих с верным по
  нормализации (`domain.answers.normalize`), перемешивание `rng.shuffle`.
  Если пул меньше `MIN_PRACTICE_CARDS` или переводов меньше 4 — `[]`.
- Никаких записей в БД и LLM.

### Репозиторий

`CardRepository.list_seen(user_id, *, limit=500) -> list[Card]` — как
`list_for_user`, но `reps > 0`, `is_suspended = False`, без порядка
(сортировка не нужна, выбор делает сервис).

### UI

- `bot/callbacks.py`: `PracticeCB(action: Literal["start", "answer"], token: int = 0, question: int = 0, option: int = 0)`.
- `bot/states.py`: `Practice.awaiting_answer`; ключи `QUESTIONS_KEY`,
  `QUESTION_INDEX_KEY`, `CORRECT_COUNT_KEY`, `PRACTICE_TOKEN_KEY`,
  `PRACTICE_ANSWER_KEY` (ответ в полёте).
- `bot/keyboards.py`: `practice_options(options, question) -> InlineKeyboardMarkup`
  (подписи — тексты переводов, обрезанные до 40 символов, `adjust(1)`;
  callback несёт индексы).
- `bot/texts.py`: `practice_question(term)`, `practice_correct(term, translation)`,
  `practice_wrong(term, translation)`, `practice_finished(correct, total)`,
  `practice_unavailable()`, `practice_offer()` (текст на пустом экране),
  `BTN_PRACTICE`.
- Главное меню: `[[ADD, REVIEW], [PRACTICE, DECKS], [STATS, HELP]]`,
  `MAIN_MENU_BUTTONS` обновляется.
- `bot/routers/practice.py` (новый):
  - `/practice`, `F.text == BTN_PRACTICE`, `PracticeCB(action="start")` → `state.clear()`,
    `build_session`; пусто → `practice_unavailable()`; иначе сохранить вопросы
    в FSM и показать первый.
  - `PracticeCB(action="answer")` → проверки свежести (состояние, токен,
    индекс вопроса, резервация); несовпадение → alert «кнопка устарела»;
    иначе резервация ставится до первых `await`, сообщение вопроса правится
    в результат, отправляется следующий вопрос или финал.
  - Никакого приёма текста: обычный текст в этом состоянии уходит в capture
    (пользователь может добавить слово, тренировка при этом прерывается
    сменой FSM-состояния — как и с повторением).
- `bot/routers/review.py`: на пустой очереди — если у пользователя хватает
  карточек (тот же порог), к `nothing_due` добавляется инлайн-кнопка
  «🏋️ Потренироваться» с `PracticeCB(action="start")`; иначе как сейчас.
- `__main__.py`: `BotCommand(command="practice", description="Тренировка")`.

### Крайние случаи

- Карточка удалена/на паузе между показом и ответом: вопрос добивается по
  данным FSM, карточка не перечитывается (переводы уже в опциях).
- Повторный/устаревший тап: состояние/токен/индекс/резервация — alert
  «Кнопка устарела», без двойного счёта.
- Перезапуск `/practice` во время сессии — новый токен, кнопки старой сессии
  перестают приниматься.
- Тренировка без единого ответа: сообщение «Тренировка завершена» не нужно —
  пользователь просто ушёл.

## Настройки

`BotSettings.practice_size: int = Field(default=10, ge=4, le=50)`.

## Тесты

- `test_domain` не нужен: правила переехали в сервис; сервисные тесты —
  `tests/test_practice.py`: сборка вопросов (4 опции, верный индекс, разные
  переводы, приоритет POS), пул с `reps=0` не попадает, меньше 4 карточек →
  пусто, детерминизм с сидированным `rng`.
- `tests/test_bot_practice.py`: `/practice` показывает вопрос; верный тап →
  правка и следующий вопрос; неверный → правильный перевод; финал со счётом;
  устаревший тап; повторный старт; кнопка из меню; инлайн-предложение на
  пустой очереди; после тренировки `reviews`/`reps` не изменились.
