# Батч G: обратное направление — карточки-близнецы

Дизайн-документ. Идея 6 дорожной карты, последняя.

## Решения человека (из Q&A)

- Как в Anki: на слово две карточки со своими расписаниями FSRS; нагрузка
  удваивается, память не смешивается.

## Мои решения (можно оспорить)

1. `cards.direction` (`forward`/`reverse`, lowercase, CHECK через тот же
   `Enum(native_enum=False)`-паттерн, что у состояния); уникальность —
   `(user_id, deck_id, term, direction)`; существующие строки — `forward`.
2. Пара создаётся в `CardService` (единственная точка создания слов): `add_draft`
   делает forward и reverse, `add_drafts` — пару на слово, но в `ImportOutcome`
   попадает только forward, чтобы счётчики «добавлено слов» не удваивались.
   Фронт-карточка возвращается вызывающим.
3. Показ: обратный фронт показывает перевод («🇬🇧 Переведите на английский») без
   термина и транскрипции; бэк — как у всех (термин, транскрипция, перевод,
   пример, бейдж). Подсказка-клоуз работает и там: пропуск не выдаёт слово.
4. Проверка ответа: обратный — сравнение с `term`, при промахе LLM-чекер с
   `direction="reverse"` (отдельный системный промпт про русское значение →
   английское слово). Тот же `matches`, скорость та же.
5. Бюджет новых слов в день остаётся **по карточкам** (как сейчас в
   `new_cards_per_day`): 20 «новых» = 20 карточек, то есть 10 слов в обе
   стороны; пара может разбиться по дням — это нормально, направления и так
   живут своими расписаниями. Формулировку README поправим.
6. Новые близнецы не показываются в одной очереди (bury для новых, как в
   Anki по умолчанию): при сборке очереди из новых карточек на слово берётся
   только одна — forward, обратная придёт следующим днём. Для «должных» карточек
   bury не делаем: их расписания уже разошлись, редкое совпадение допустимо и
   фиксируется как поведение.
7. Практика и экспорт работают с forward-карточками: `list_seen` и
   `list_for_user` получают параметр направления (дефолт forward для практики;
   экспорт — forward). Иначе квиз спрашивал бы одно слово дважды, а CSV
   содержал бы дубли.
8. Пауза и удаление применяются к паре (симметрично), чтобы лечение leech не
   оставляло близнеца в очереди. Обогащение (примеры/мнемоника) — по
   конкретной карточке; расхождение пары допустимо и фиксируется как
   отложенное.
9. Статистика честно удваивается по карточкам (как в Anki); отдельного
   «слов»/«карточек» не различаем — README предупреждает.
10. Старым словам (до миграции) обратные близнецы **не создаются** — это
    осознанное решение: массовая догенерация перекосила бы очередь и статистику,
    а ленивое создание — скрытая запись в потоке повторения. Новые слова
    получают пару с момента добавления.
11. Синоним на обратной карточке — «почти» (HARD): слово по смыслу подходит, но
    карточка проверяет конкретное слово, и полным «верно» это не считается;
    EASY за него не даётся. Полное совпадение и мелкие опечатки — «верно».

## Не-цели

- Отдельная настройка «только forward» на слово; разбиение статистики
  слова/карточки; синхронизация enrichment между близнецами; клоуз-вопрос
  вместо close-подсказки (это уже сделано в A).

## Дизайн

### Модель и миграция

- `Card.direction: Mapped[CardDirection]` (Enum, default FORWARD,
  server_default `forward`); UniqueConstraint расширяется; миграция заполняет
  существующие строки `forward` (server_default).
- `domain/enums.py`: `CardDirection(StrEnum)`.

### Репозиторий

- `CardRepository.add(..., direction=CardDirection.FORWARD)`.
- `find_twin(card) -> Card | None` (тот же user/deck/term, другое направление).
- `list_for_user(..., direction: CardDirection | None = None)`.
- `list_seen(..., direction=CardDirection.FORWARD)`.

### Сервис

- `CardService.add_draft`: создаёт пару, возвращает forward.
- `CardService.add_drafts`: пары на слово, в outcome — forward.
- `CardService.suspend/delete`: применяют к близнецу.

### Ревью и проверка

- `texts.card_front(card)` — ветка reverse (подпись «🇬🇧 Переведите на
  английский», перевод крупно; без термина/транскрипции).
- `AnswerChecker.check(..., direction="forward")`; новые
  `ANSWER_CHECK_REVERSE_SYSTEM_PROMPT` и `build_answer_check_prompt(...,
  direction=...)`.
- `AnswerGradingService._verdict`: ожидаемое — `term` для reverse; чекер с
  направлением.

### Экспорт/импорт/практика

- `files.py` экспорт — `direction=FORWARD` (round-trip: импорт снова создаст
  пару).
- `PracticeService` — `list_seen` по умолчанию forward.

## Крайние случаи

- Дубликат: `find_by_term` ищет любое направление — повторное добавление слова
  отклоняется, пара не раздваивается.
- Импорт CSV с существующим словом — как раньше (дубликат).
- Обратный ответ латиницей: опечатки через LLM-чекер (как сейчас для русских).
- Без LLM: обратный ответ — только точное совпадение (тихое поведение).
- Практика/квиз больше не показывает слово дважды.
- Удаление одной карточки удаляет пару.

## Тесты

- `test_services.py`: `add_draft` создаёт пару; `add_drafts` — пары, счётчики
  по словам; `suspend`/`delete` симметричны; повторный add отклоняется.
- `test_domain_answers.py`/`test_grading.py`: обратный вердикт (точное
  совпадение; через чекер с `direction="reverse"`; без модели — WRONG).
- `test_llm_checker.py`: промпт/система reverse, алиасы те же.
- `test_bot_flow.py`-стиль (новый `test_bot_reverse.py`): обратный фронт
  показывает перевод и не показывает термин; правильный английский ответ
  оценивается; подсказка-клоуз работает; бэк показывает всё.
- `test_csv_io`/`test_bot_files.py`: экспорт без дублей; импорт создаёт пару.
- `test_practice.py`: одно слово — один вопрос.
- Интеграционный: миграция, уникальность пары, старые строки forward.
