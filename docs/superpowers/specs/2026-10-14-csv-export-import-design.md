# Батч C: экспорт и импорт CSV

Дизайн-документ. Идея 8 дорожной карты: выгрузка своих слов файлом и загрузка
списка слов файлом, без FSRS-состояния.

## Зачем

Слова должны покидать бота и возвращаться: бэкап, перенос в Anki, добавление
больших списков из таблиц — без поштучного ввода в чат.

## Решения человека (из Q&A)

- CSV в обе стороны. Контент без FSRS-состояния; переводы дозаполняет LLM,
  если подключена.

## Мои решения (можно оспорить)

1. Формат: разделитель `;`, кодировка UTF-8 с BOM (открывается в Excel),
   колонки: `term;translation;transcription;part_of_speech;example;notes;tags;deck`.
   `tags` — через `|`. Экспортируется первый пример карточки.
2. Импорт: разделитель распознаётся среди `; , \t`, заголовок необязателен
   (если первая ячейка — `term`/`слово`, строка пропускается), колонки
   позиционные, лишние хвостовые отбрасываются. Без `term` строка
   пропускается; без `translation` — заполняется LLM (до 30 терминов одним
   вызовом), иначе строка пропускается со счётчиком.
3. Лимиты: файл ≤ 1 МБ, ≤ 1000 строк; константы модуля.
4. Колоды: строка с `deck` попадает в колоду с этим именем (создаётся при
   отсутствии), пустая — в основную. Дедуп — по термину в масштабе
   пользователя (как везде).
5. Предпросмотр перед сохранением: счётчики (новые/дубли/без перевода), первые
   10 строк, кнопки «✅ Сохранить»/«❌ Отмена» (свои колбэки и своё FSM-состояние).
6. Вход: `/export`, `/import` (объясняет, что прислать файл) и любое вложение
   `.csv`/`.txt` в чате.
7. Перевод: бюджет — 30 терминов на импорт, один вызов (`MAX_TRANSLATION_FILL`);
   остальные строки без перевода пропускаются и видны в счётчике. Ошибка или
   квота модели — то же поведение (счётчик + примечание), без отдельного
   состояния.
8. Чистка импортируемых полей — теми же правилами, что у `ParsedCard`
   (flatten, лимиты, lowercase POS, теги), плюс усечение до ширин колонок
   (`part_of_speech` 32, `transcription` 128, имя колоды — по модели).
   Многострочные `notes`/`example` схлопываются в одну строку — цена
   консистентности и защиты от prompt injection.

## Не-цели

- Никакого импорта Anki `.apkg` (отложено отдельным решением человека).
- Никакого обмена колодами, никаких FSRS-полей в файле.

## Дизайн

### Чистый формат — `services/csv_io.py`

```python
CSV_DELIMITER = ";"
MAX_FILE_BYTES = 1_000_000
MAX_ROWS = 1000

@dataclass(frozen=True, slots=True)
class CsvRow:
    term: str
    translation: str | None
    transcription: str | None = None
    part_of_speech: str | None = None
    example: str | None = None
    notes: str | None = None
    tags: tuple[str, ...] = ()
    deck: str | None = None

@dataclass(frozen=True, slots=True)
class CsvParseResult:
    rows: list[CsvRow]
    skipped: int          # строки без term / пустые / сверх лимита
    empty_translations: int

def cards_to_csv(cards: Sequence[Card]) -> str
def parse_cards_csv(text: str) -> CsvParseResult
```

- `cards_to_csv`: `csv.writer` с `;`, `\r\n`, заголовок, BOM добавляет
  вызывающий (кодирование `utf-8-sig`).
- `parse_cards_csv`: `csv.Sniffer` с фолбэком на `;`; обрезка BOM; заголовок;
  до `MAX_ROWS`; `tags` сплитятся по `|` и `,`; пустые поля → None.

### Переводчик терминов — `services/llm/translator.py`

`TermTranslator.available`; `translate(terms, user_id) -> dict[str, str]` —
новый LLM-компонент по образцу enricher: схема `TranslationsResponse` (записи
`term`/`translation`, чистка как у ParsedCard), промпт «переведи на русский
кратко, верни JSON». Контейнер: `Services.translator`.

### Поток импорта

- `bot/routers/files.py` (новый):
  - `/export`: `cards.list_for_user(user.id, limit=5000)` → `cards_to_csv` →
    `BufferedInputFile(encoded, filename=f"eng-remember-{date}.csv")` →
    `message.answer_document`.
  - `/import`: текст-инструкция.
  - `F.document` (csv/txt по имени): `_read_document(bot, message) -> bytes`
    (скачивание; отдельная функция — точка подмены в тестах), лимит байт,
    декодирование `utf-8-sig` с фолбэком `utf-8`/`cp1251`, `parse_cards_csv`.
  - Дедуп: `cards.existing_terms` + дедуп внутри файла (регистронезависимо).
  - Заполнение переводов через `translator`, если есть модель и есть
    пропущенные (до 30).
  - Предпросмотр и `state.set_state(ImportFile.confirming)`; в FSM — строки
    как словари (сериализуемо), счётчики.
  - `FileImportCB(action="confirm"|"cancel")`: confirm — резолв колод
    (`decks.get_by_name` / `decks.create` / `card_service.default_deck`) и
    `card_service.add_drafts` по группам; итог — `texts.file_import_result`
    (добавлено/пропущено/по колодам); cancel — сообщение об отмене.
- `bot/callbacks.py`: `FileImportCB` (prefix `fi`).
- `bot/states.py`: `ImportFile.confirming`; ключи `FILE_ROWS_KEY` (и при
  необходимости счётчиков).
- `bot/keyboards.py`: `file_import_confirm()`.
- `bot/texts.py`: инструкция, предпросмотр, результат, отмена, ошибки
  (слишком большой файл, пустой файл, битая кодировка).
- `__main__.py`: `BotCommand("export")`, `BotCommand("import")`; README и
  `welcome_new` — строка про экспорт/импорт.

### Крайние случаи

- Файл без строк/с одним заголовком → «ничего не нашёл», состояние не
  меняется.
- Дубликаты внутри файла и существующие слова — в счётчики, не ошибка.
- Импорт при недоступной модели: строки без перевода пропускаются, в
  предпросмотре явно сказано сколько.
- Повторное нажатие «Сохранить»/старые кнопки → alert «кнопка устарела»
  (состояние + отсутствие данных).
- Имя колоды с `;`/переводом строки — csv-экранирование на экспорте, никаких
  ограничений на импорте (имя — как есть, максимум длины Deck.name).

## Тесты

- `test_csv_io.py`: экспорт-строки (заголовок, `;`, `|` в тегах), парсинг с
  `,`/`\t`/`;`, BOM, заголовок, строки без term, отсутствие перевода, лимит
  строк.
- `test_llm_translator.py`: ответ модели, отсутствие модели, `user_id` в
  вызове.
- `test_bot_files.py`: `/export` шлёт документ с ожидаемым содержимым;
  `/import` инструкция; вложение обрабатывается (подмена `_read_document`),
  предпросмотр и подтверждение создают карточки в нужных колодах; дубликаты и
  слова без перевода — в счётчиках; с LLM перевод дозаполняется; отмена;
  устаревшая кнопка; слишком большой/пустой файл.
