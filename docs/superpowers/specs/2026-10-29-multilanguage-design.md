# Мультиязычность: 17 изучаемых языков

Дизайн-документ. Расширение eng-remember с английского на 17 изучаемых
языков. Русский остаётся единственным языком перевода. Основной путь — LLM;
без неё бот деградирует до разбора пар и точного совпадения.

## Решения человека (из Q&A)

- Изучаемый язык — свойство карточки, а не пользователя: у обычного человека
  все карточки на одном языке, у полиглота могут соседствовать разные.
- Язык перевода — всегда русский, пользователь его не меняет.
- Язык определяется автоматически при добавлении слова.
- Спорные слова на латинице по умолчанию считаются английскими, если язык не
  указан в тексте.
- На карточке добавления язык показывается явно; если угадали неверно,
  пользователь указывает нужный язык в тексте сообщения.
- При повторении явно написано, какой язык ожидается в ответе.
- Китайский — только мандарин (`cmn`), арабский — только стандартный (`arb`),
  без диалектов.
- Поддерживаем 17 языков: `eng`, `cmn`, `hin`, `spa`, `arb`, `fra`, `ben`,
  `por`, `ind`, `deu`, `jpn`, `vie`, `swh`, `tur`, `kor`, `tha`, `ita`.
- Если в запросе нет слова, по которому определяется язык, — английский.
- LLM — основной путь; без неё — сильно упрощённый фоллбэк.

## Мои решения (можно оспорить)

1. `cards.language` — ISO 639-3, `String(8)`, not null, default `eng`.
   Существующие карточки получают `eng`; отдельных данных для миграции нет.
2. `CardDraft.language` — обычное поле, default `eng`; `normalized()` его
   сохраняет и приводит к поддерживаемому коду. Это важно: `CardDraft`
   пересоздаётся в `normalized()`, и забытое поле молча превратило бы
   французскую карточку в английскую.
3. Реестр языков — `src/eng_remember/domain/languages.py`: код, русское имя,
   английское имя для промптов, флаг, письменность, признак RTL, форма
   «на французском» для обратной карточки. Один источник правды для UI и
   промптов.
4. LLM-парсер возвращает `language` у каждой карточки и `language` верхнего
   уровня у ответа. Верхнеуровневый язык — это **язык, на котором нужно
   подобрать слова**, а не обязательно язык каждой карточки. Он нужен для
   запросов без готовых карточек («ещё 10 слов про медицину на китайском») и
   для подбора из текста. Приоритет: явно названный язык подбора → язык
   карточки-затравки/текста → `eng`. Валидатор принимает ISO 639-1 (`fr`,
   `zh`, `ar`, `en`), региональные теги (`fr-FR`, `pt-BR`, `zh-Hant`,
   `en-US`), названия языков и алиасы, приводит к ISO 639-3; неизвестное —
   `eng`.
5. Если модель вернула карточку без языка или с неизвестным кодом, карточка
   получает `eng`. Это осознанный дефолт: лучше английская карточка, чем
   потерянная. Промпт отдельно просит не создавать карточки для языков вне
   списка, а отвечать через `intent="explain"`.
6. Подбор слов (`expand`) всегда наследует **язык подбора** из
   `ParseResponse.language`: все карточки, пришедшие из `ExpansionResponse`,
   получают этот язык, а не тот, что модель написала в каждой карточке.
   Иначе при китайском запросе одна забытая карточка стала бы английской.
   Если в одном сообщении просят английское слово и французские слова по
   теме, карточка сохраняется как английская, а подбор идёт на французском:
   «ещё слова» не обязаны совпадать по языку с добавленным словом.
7. Фоллбэк без LLM определяет язык по письменности: ханьцзы → `cmn`, кана →
   `jpn`, хангыль → `kor`, арабская вязь → `arb`, деванагари → `hin`,
   бенгальская → `ben`, тайская → `tha`, латиница → `eng`. Кириллица и
   неподдерживаемые письменности отвергаются, как сейчас отвергается
   русско-английская путаница. Латинские языки без LLM не различаются:
   французский, испанский и итальянский станут английским.
8. `CardDraft.language` участвует в проверке дублей. Один и тот же `hotel`
   на английском и французском — разные карточки. Уникальный ключ карточки
   становится `(user_id, deck_id, term, language, direction)`.
9. Проверка ответа: точное совпадение сначала, затем LLM. Для прямого
   направления ожидается русский ответ, для обратного — слово на изучаемом
   языке. Нормализация языка:
   - общая: NFKC, `casefold`, пунктуация и символы → пробел, схлопывание
     пробелов;
   - русский: плюс `ё → е`;
   - арабский: убираются харакаты и татвиль, варианты алифа и йа
     приводятся к базовым;
   - остальные: без снятия диакритики, потому что в хинди, бенгальском и
     тайском она часть слова, а во французском, испанском и португальском
     меняет смысл (`ou`/`où`, `si`/`sí`, `el`/`él`). Пропущенный акцент —
     это не точное совпадение, а случай для LLM-чекера («почти» или
     «верно», если слово узнаваемо);
   - китайский: NFKC не объединяет упрощённые и традиционные иероглифы.
     В v1 карточка хранится в той письменности, которую написал
     пользователь/модель; по умолчанию модель просят использовать
     упрощённый китайский. LLM-чекер принимает варианты иероглифов, но
     точное совпадение и проверка дублей различают `书` и `書`. OpenCC и
     конвертация письменностей — не в этой версии.
10. `matches()` для русского по-прежнему принимает варианты через запятую,
    точку с запятой, слэш и вертикальную черту. Для изучаемого языка
    сравнивается целая нормализованная строка: запятая может быть частью
    фразы, а не списком синонимов.
11. Подсказка-`cloze`: для `cmn` и `jpn` — точное вхождение подстроки
    (китайский и японский пишутся без пробелов); для остальных нелатинских
    письменностей — точное совпадение слова или консервативный префикс; для
    латиницы и кириллицы — Unicode-aware границы слова и текущее
    стем-правило. Регулярка `[A-Za-z]` заменяется на `[^\W\d_]` с
    `re.UNICODE`, иначе `hôtel`, `café`, `São` и `İstanbul` не находятся;
    апостроф в `l’hôtel` не должен мешать найти `hôtel`. Если уверенного
    совпадения нет, пример возвращается нетронутым, как сейчас.
12. Проверка «слово действительно есть в тексте» (`appears_in_text`) тоже
    становится языковой: для `cmn`/`jpn` — подстрока; для остальных
    нелатинских — нормализованное вхождение в токен; для латиницы и
    кириллицы — Unicode-aware токенизация и текущее стем-правило. При
    сомнении слово отбрасывается.
13. Практика не меняется: варианты ответа — русские переводы, поэтому
    смешивать языки в одном квизе не страшно. Язык термина на выбор не
    влияет.
14. CSV: в конец добавляется необязательная колонка `language`. Экспорт её
    пишет; старые файлы без неё импортируются как раньше, язык берётся из
    письменности, латиница → `eng`. Если колонка есть, значение проходит
    через тот же валидатор.
15. `/language` не добавляем. Дефолт — английский; явное указание языка в
    тексте («французское слово hotel — отель») перекрывает дефолт. Это
    осознанно оставлено на будущее: одна команда и меню из 17 языков — это
    отдельная работа, а текущий сценарий закрывается текстом.
16. CEFR остаётся одним уровнем пользователя и приблизительной оценкой для
    всех языков. HSK, JLPT и прочие экзаменационные шкалы — не в этой
    версии. `/level` перестаёт говорить «уровень английского» и говорит
    «уровень изучаемого языка».
17. Транскрипция — best-effort и зависит от языка: IPA для европейских,
    пиньинь для `cmn`, ромадзи для `jpn`, IAST для `hin`/`ben`, латинская
    транслитерация для `arb`/`tha`. Если модель не уверена, поле можно не
    заполнять.
18. Промпты становятся языконейтральными: язык передаётся в user-промпт из
    реестра, а не зашит в system-промпт. Исключение — промпт парсера: он
    содержит список поддерживаемых языков и правила определения, потому что
    именно он решает, какой язык у карточки.

## Не-цели

- Локализация интерфейса бота: UI остаётся русским.
- Другой язык перевода, кроме русского.
- Диалекты китайского (юэ, у, миньнань) и арабского (египетский,
  левантийский, суданский).
- Отдельные шкалы HSK/JLPT и статистика по ним.
- Аудио, произношение, оценка речи.
- Колода на каждый язык; колоды остаются смешанными, язык живёт на карточке.
- Команда `/language` и запоминание «активного» языка пользователя.
- Языки вне списка 17: бот объясняет, что пока не поддерживает их.
- Редактирование языка уже сохранённой карточки. Язык задаётся при
  добавлении; исправить можно, удалив карточку и добавив заново.

## Дизайн

### Реестр языков

`domain/languages.py`:

```python
@dataclass(frozen=True, slots=True)
class Language:
    code: str          # ISO 639-3
    name_ru: str       # «Французский»
    name_en: str       # «French» — для промптов
    flag: str          # «🇫🇷»
    script: str        # «latin», «han», «arabic», …
    rtl: bool = False
    name_ru_in: str = ""  # «на французском» — для обратной карточки
```

Порядок в `SUPPORTED_LANGUAGES` — по распространённости, как в списке выше.
Флаги — символы, а не политическое утверждение; для португальского,
суахили и арабского выбран один представительный флаг.

`DEFAULT_LANGUAGE = "eng"`, `NATIVE_LANGUAGE = "rus"`. `rus` есть в реестре
для отображения русского ответа и нормализации, но отсутствует в списке
изучаемых языков. `language_for_code()` возвращает `None` для неизвестного;
`resolve_language()` приводит алиасы и неизвестное к `eng`; `language_badge()`
даёт строку `🇫🇷 Французский`.

### Данные и миграция

- `Card.language: Mapped[str] = mapped_column(String(8), nullable=False,
  default="eng", server_default="eng")`.
- `CardDraft.language: str = "eng"`.
- `CardDraft.normalized()` передаёт `language=resolve_language(self.language)`.
- `CardRepository.add()` сохраняет `cleaned.language`.
- `CardRepository.find_by_term(user_id, term, language)` фильтрует по языку;
  `find_twin()` тоже сравнивает `Card.language`.
- `CardRepository.all_terms()` и `existing_terms()` принимают
  `language: str | None`; для подбора и импорта передаётся язык, чтобы
  английский `hotel` не считался известным французским `hotel`.
  Смешанная пачка группируется по языку: сервис вызывает `existing_terms`
  для каждой языковой группы и строит множество пар
  `(language, term.casefold())`. Это дешевле, чем новый API, и исключает
  ложные пропуски и `IntegrityError` на пачке из разных языков.
- `CardService.add_draft()`/`add_drafts()` передают язык в проверку дублей и
  в репозиторий. В `add_drafts()` ключ «уже видели в этой пачке» —
  `(language, term.casefold())`.
- Уникальный ключ: `uq_cards_user_id_deck_id_term_language_direction` по
  `(user_id, deck_id, term, language, direction)`. Старый
  `uq_cards_user_id_deck_id_term_direction` удаляется.
- Alembic: одна миграция — `add_column` с `server_default="eng"`, `drop_constraint`,
  `create_unique_constraint`. Старые строки заполняются дефолтом; отдельный
  backfill не нужен.
- `update_content()` язык не меняет: язык карточки неизменяем после создания.

### Определение языка

LLM-парсер:

- В system-промпте — список 17 языков с кодами и русскими/английскими
  именами. Русский явно помечен как язык перевода, не цель.
- Правило: «Определи язык термина. Если пользователь назвал язык — используй
  его. Если термин на латинице и может принадлежать нескольким языкам, а
  язык не назван, используй `eng`. Если язык вне списка — не создавай
  карточку, ответь через `intent="explain"`».
- `ParsedCard.language` — ISO 639-3. Валидатор: lower-case, `_` → `-`,
  алиасы `en→eng`, `zh→cmn`, `zh-cn→cmn`, `ar→arb`, `fr→fra`, `es→spa`,
  `de→deu`, `ja→jpn`, `ko→kor`, `it→ita`, `pt→por`, `hi→hin`, `bn→ben`,
  `id→ind`, `vi→vie`, `sw→swh`, `tr→tur`, `th→tha`; региональные теги
  отбрасывают подтег и маппятся на базу (`fr-FR→fra`, `pt-BR→por`,
  `zh-Hant→cmn`, `en-US→eng`, `es-MX→spa`, `de-AT→deu`, `ar-SA→arb`);
  неизвестное → `eng`. Диалект арабского (`ar-EG`) маппится на `arb` только
  как запасной вариант: промпт просит объяснить, что поддерживается только
  стандартный арабский.
- `ParseResponse.language` — **язык подбора**, а не обязательно язык
  карточек. Приоритет: явно названный язык подбора → язык карточки-затравки
  или исходного текста → `eng`. Для `add_cards` без `more_words` значение
  не используется, но заполняется языком первой карточки. Для `expand` —
  язык слов, которые надо найти (не обязательно язык текста, если
  пользователь просит слова на другом языке). Дефолт `eng`.
- `ExpansionResponse` не доверяет языку отдельных карточек: `WordExplorer`
  перезаписывает его языком запроса.
- Для текста: по умолчанию язык — доминирующий не-русский язык текста. Если
  пользователь явно просит слова на другом языке, побеждает явное указание;
  текст остаётся источником, а язык подбора — запрошенный.

Фоллбэк:

- `parse_text()` извлекает транскрипцию до проверки языка (иначе пиньинь в
  скобках перевесит иероглифы и термин станет английским).
- `detect_script_language(text)` считает буквы по письменностям; при
  нескольких — доминирующая. Кана важнее ханьцзы (японский), хангыль —
  корейский. Ханьцзы без каны — `cmn` (японские слова только из кандзи в
  фоллбэке будут мандаринскими; это известное ограничение).
- Латинские языки → `eng`. Кириллица, греческий, иврит, тамильский и другие
  неподдерживаемые письменности → термин отвергается.
- Добавить полноширинные разделители `：`, `；` и китайские скобки в
  регулярки парсера, чтобы `书（shū）— книга` разбиралось.

### Промпты

- `PARSE_SYSTEM_PROMPT` — генерируется из реестра (список языков) и содержит
  правила определения. В карточке: `term` — слово в изучаемом языке,
  `translation` — по-русски, `examples` — на изучаемом языке, `notes` —
  по-русски, `transcription` — в нотации языка. Добавить короткий пример
  неанглийской карточки (`bonjour — здравствуйте`, `fra`).
- `EXPANSION_SYSTEM_PROMPT` — без «English»: «You suggest vocabulary in the
  target language named in the request for a Russian-speaking learner».
  `build_expansion_prompt(..., language)` добавляет
  `Target language: French (fra). Translation language: Russian.`
- `ANSWER_CHECK_SYSTEM_PROMPT` / `_REVERSE_` — без «English»; язык приходит
  в user-промпте как `<target_language>French</target_language>`. Добавить:
  «Небольшие орфографические варианты, не меняющие слово (арабская
  диакритика, варианты иероглифов), считаются верными».
- `ENRICH_EXAMPLES_SYSTEM_PROMPT` — примеры на изучаемом языке; уровень
  B1–B2 или эквивалент.
- `MNEMONIC_SYSTEM_PROMPT` — «for a Russian speaker learning the target
  language»; для нелатинских письменностей разрешить звук, написание или
  компоненты иероглифа.
- `TRANSLATION_SYSTEM_PROMPT` — «Translate vocabulary in the target language
  into Russian».
- `build_*_prompt()` принимают `language: str` и берут английское имя из
  реестра. Язык в промпт попадает только из реестра, не из текста
  пользователя.

### Проверка ответа

- `AnswerChecker.check(..., language=card.language)`.
- `AnswerGradingService._verdict()`:
  - прямое направление: `matches(typed, card.translation, NATIVE_LANGUAGE)`;
  - обратное: `matches(typed, card.term, card.language)`.
- `domain/answers.py`: `normalize(text, language=NATIVE_LANGUAGE)`,
  `matches(answer, expected, language=NATIVE_LANGUAGE)`. `translation_variants`
  остаётся русским и используется для прямого направления и практики.
- Для арабского — снятие харакатов/татвиля и унификация алифа/йа; для
  китайского — NFKC (полноширинные формы); для остальных — общая
  нормализация без снятия диакритики.
- LLM-чекер получает язык карточки; при отсутствии модели — точное
  совпадение с языковой нормализацией.

### Подсказки и примеры

- `cloze(example, term, language=DEFAULT_LANGUAGE)`:
  - `cmn`/`jpn` — все точные вхождения подстроки;
  - остальные нелатинские — точное слово или консервативный префикс;
  - латиница/кириллица — текущее стем-правило;
  - нет уверенного совпадения — пример без изменений.
- `appears_in_text(term, text, language=DEFAULT_LANGUAGE)` — та же логика:
  подстрока для CJK, нормализованное вхождение в токен для остальных
  нелатинских, стем для латиницы.
- `EnrichmentService` передаёт `card.language` в промпты примеров и
  мнемоники.
- `review.py` вызывает `cloze(example, card.term, card.language)`.

### UI

Прямая карточка:

```
🇫🇷 Французский · переведите на русский

bonjour
существительное

Learning · повторений: 3
```

Обратная карточка:

```
🇫🇷 Французский · напишите слово на французском

здравствуйте

Learning · повторений: 1
```

Превью добавления:

```
Разобрал 2 слова:

• 🇫🇷 bonjour /bɔ̃ʒuʁ/ · B1 · частое
   здравствуйте
• 🇨🇳 书 /shū/ · A1 · частое
   книга

Если язык определён неверно, укажите его в сообщении:
«французское слово hotel — отель».
```

- `texts.card_front` показывает флаг, русское имя языка и ожидаемое
  направление. Прямое: «переведите на русский». Обратное: «напишите слово
  на {name_ru_in}».
- `texts.card_back` оставляет `🇷🇺` у русского перевода; у термина можно
  показать флаг языка.
- `texts.cards_listing` добавляет `language_badge(draft.language)` к каждой
  карточке. Это покрывает и превью добавления, и найденные слова.
- Превью добавления показывает подсказку про исправление языка, если
  `engine != "rules"`. В режиме без модели вместо неё — честная строка:
  «Без модели язык определяется по письменности; латиница считается
  английской».
- `file_import_preview` показывает язык у строк; `file_import_prompt`
  упоминает необязательную колонку `language`.
- `/help` и приветствие: «иностранные слова», список языков, пример
  исправления языка. `/level` — «уровень изучаемого языка».
- `__main__`: описание `/level` без «английского».

### CSV

- `_HEADER` дополняется `language` в конце:
  `term;translation;transcription;part_of_speech;example;notes;tags;deck;language`.
- `CsvRow.language: str | None`.
- `cards_to_csv` пишет `card.language`.
- `parse_cards_csv` читает девятый столбец; старые файлы дают `None`.
- `_clean_row`/`_row_to_draft`/`_row_to_dict`/`_rows_from_state` носят язык.
  При отсутствии — `detect_script_language(term) or DEFAULT_LANGUAGE`.
- Дубли в импорте считаются по `(language, term.casefold())`.
- `translator.translate(..., language)` — переводы на русский; строки разных
  языков группируются, чтобы промпт не смешивал языки.

### Фоллбэк

- Разбор пар работает как сейчас, но принимает нелатинские термины
  поддерживаемых письменностей.
- Определение языка — по письменности.
- Проверка ответа — точное совпадение с языковой нормализацией.
- Примеры, транскрипция, CEFR, подбор по теме — недоступны, как и сейчас для
  английского.
- Явное указание языка («французское слово …») в фоллбэке не разбирается:
  это ограничение упрощённого режима, и подсказка в превью это учитывает.

### Крайние случаи

- Латиница, общая для нескольких языков (`hotel`, `radio`, `pizza`) →
  `eng`, пока язык не назван.
- `bonjour` без указания языка → LLM определяет `fra`; фоллбэк → `eng`.
- Ханьцзы без каны → `cmn`; японское слово только из кандзи в фоллбэке
  станет мандаринским.
- Смешанная пачка карточек разных языков: карточки сохраняются с разными
  языками; «ещё слова» использует язык подбора из запроса. Если язык
  подбора не назван, берётся язык первой карточки — для смешанной пачки это
  эвристика, а не обещание.
- Один и тот же термин на разных языках — разные карточки благодаря языку в
  уникальном ключе.
- Старые карточки и старые CSV без языка — `eng`.
- Пропущенный акцент во французском/испанском/португальском не проходит
  точное совпадение, но LLM-чекер может засчитать его как «почти» или
  «верно».
- `书` и `書` — разные карточки в v1; LLM-чекер принимает варианты, точное
  совпадение и дубли — нет. Модель по умолчанию просят упрощённый китайский.
- Арабская диакритика в ответе не мешает точному совпадению.
- Китайский без пробелов: `cloze` и проверка текста работают подстрокой.
- RTL-термины: Telegram сам разворачивает строку; подписи бота остаются
  русскими, HTML экранируется как раньше.
- Модель вернула неизвестный код → `eng`; пользователь увидит бейдж и
  сможет переотправить с явным языком.
- Запрос языка вне списка → `intent="explain"` с ответом «пока не
  поддерживаю»; если модель всё же вернула карточку, сработает дефолт `eng`.

### FSM и сохранение состояния

- `CardDraft` сериализуется в FSM через `asdict`, поэтому `language`
  попадает в состояние автоматически.
- `_present` дополнительно хранит `LANGUAGE_KEY` — **язык подбора** из
  `DiscoveryResult.language`/`response.language`, а не язык первой своей
  карточки. Он нужен кнопке «Ещё слова», которая пересобирает
  `ParseResponse` без исходного сообщения. Если подбора не было, значение
  не используется.
- `_ask_clarification` хранит язык; `clarify_without_answer` передаёт его в
  пересобранный `ParseResponse`.
- `DiscoveryResult.language` и `run_discovery(..., language=...)` носят язык
  через весь путь.
- CSV-строки в FSM (`_row_to_dict`/`_rows_from_state`) носят `language`.
